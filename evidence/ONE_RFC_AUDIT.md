# Why 1RFC Stalled at Module B

## Repository result

The audited `1RFC` main branch contained 245 commits, 385 non-Git files, 13 registered runs, multiple overlapping state/context records, and a root bootstrap requiring a long chain of governance and context checks. Recent history was dominated by lifecycle, context-packet, horizon, authority, and mapping work. The admitted Module B plan itself was referenced as an external Library object rather than committed as readable scientific content.

That machinery successfully protected provenance, but it made the next scientific action difficult to see and expensive for a chat iteration to recover. It also created many ways for equivalent state records to disagree.

## Scientific result

Module A contains the strongest reusable advance:

- it corrects the N-body add-one-body theorem;
- separates source-preserving refinement from unchanged dynamics;
- constructs witnessed routes and singleton normalization on maximal noncollision intervals;
- defines event packets, no-loss signatures, typed memory, promotion, and dormancy;
- supports an append-only event-ancestry order while explicitly denying that kernel depth is physical time;
- keeps collision continuation and all-time regularity outside the proved scope.

Module B then proves useful finite-graph algebra:

- a positive graph-resolvent compression operator;
- spectral smoothing and total-mode preservation;
- a graph continuity/current ledger;
- orthogonal subspace decompositions;
- stable compression and tail semigroups.

The stall occurs because those results were declared “physical” by predicates or names before deriving the physical-realization interface. The open continuum/physical obligations were acknowledged, but the plan moved toward contract freeze, first execution, ensembles, and closeout instead of first proving causal geometry, dimensions, an action/evolution law, stress-energy or its discrete analogue, refinement, and observables.

## Fresh-repository correction

2-RFC keeps the scientific results and removes the operating-system layer:

- one machine state file;
- one plan;
- one active proof file;
- one validation command;
- no run-number theater;
- no duplicate context caches;
- no automatic promotion from algebra to physics;
- no downstream work while the realization bridge is open.

This audit is diagnostic provenance only. Historical failed numerical states and obsolete execution lineages are not parents of the new proof.
